# Publication, blog, and release checklist

Use this checklist only after a reproducible result exists. A workshop
submission, paper acceptance, hardware result, or external response is not
guaranteed.

## Evidence and writing

- [ ] State the research question and contribution narrowly.
- [ ] Verify citations against primary sources and follow venue citation rules.
- [ ] Describe environment, controllers, baselines, training budget, seeds, and
  analysis sufficiently for reproduction.
- [ ] Report negative and failed results as well as successful runs.
- [ ] Separate simulated proxies, measured GPU/CPU power, and neuromorphic
  hardware energy.
- [ ] Include limitations, uncertainty, and deviations from the protocol.
- [ ] Ensure every figure is generated from the released results/scripts.

## Artifact and release

- [ ] Verify a clean checkout can run the documented small example.
- [ ] Include configurations, dependency versions, test instructions, and license.
- [ ] Review dataset/model/code licenses and attribution requirements.
- [ ] Remove secrets, private data, and unnecessary large generated artifacts.
- [ ] Tag a release and archive the exact code revision used for reported results.
- [ ] Add a concise demo video/GIF only if it accurately represents a reproducible run.

## Venue and communication

- [ ] Verify venue scope, deadline, anonymity rules, page limits, and artifact policy.
- [ ] Obtain any required advisor/coauthor review and approval.
- [ ] For outreach, send a concise message with the question, evidence, limitations,
  and stable artifact links. Do not imply endorsement or guaranteed opportunity.
